## Booster presentation lifecycle

The original code unconditionally grabbed the first reveal button's focus and treated raw focus as hover even in mouse mode. It could activate hover presentation before all cards had finished dealing. It also prepended a full CardHoverTip for a card already shown and placed pooled NCard instances beneath a veil destroyed by ordinary QueueFree, bypassing their native pool return protocol. These are source-verifiable lifecycle defects. Exact reproduction and visual acceptance of the user's intermittent top-left symptom remain K6's native UI responsibility.

The correction uses ordinary instances of the same native card scene for short-lived opening views. The original card models, slots, contents and native selection screen are retained. Automatic focus transfer occurs only in controller mode, after all dealing finishes; input is ignored while a slot deals/flips. Hover derives from actual local pointer containment or current controller focus, with mode/resize refresh. Already displayed cards expose their normal keyword hover tips instead of a duplicate self-card. Each presentation tween, hover tip and input-mode subscription is cleaned up on exit. The veil hides before native controls are restored, and the native selection/result path resumes unchanged.

The native `FocusedControlFromTopBar` getter is a separate entry point. Its additional narrow Harmony prefix delegates directly to the existing `OpeningFocus.Prefix`, sharing the same CWT resolver and deal gates. Without an active opening, both getters retain native fallback; cleanup removes the entry. The Topbar-only freeze was `c720e688cc90f3c9e4c0d77f2f813b0463db49b800b7f25c8f36cb95627391af`; the subsequent tooltip correction below supersedes it. K6 must verify final DLL target activation. Physical-controller interaction remains NOT TESTED unless separately exercised with the real input device.

The current correction follows the actual native NCardHolder hitbox contract: explicitly Connect `NClickableControl.Focused` and `Unfocused` with native callables. Only these aggregated native signals update a local focus flag; RefreshTips requires that flag plus the existing dealt/flipping/enabled/visible gates. It no longer synthesizes hover from geometry at reveal completion. The hitbox keeps MouseFilter.Stop throughout dealing/flipping, while native Disable/Enable and the existing action guards block premature input. The [Godot 4.5 mouse-filter contract](https://docs.godotengine.org/en/4.5/classes/class_control.html#enum-control-mousefilter) confirms that Ignore suppresses GUI mouse signals; the implementation no longer switches this filter during the reveal lifecycle. Native Unfocused clears only that owner's tip set. There is no frame poller, global tip clear, extra input system or model change. Debug-level `BOOSTER UI` messages identify native focus transitions and deal/flip/face-up state for diagnosis.
